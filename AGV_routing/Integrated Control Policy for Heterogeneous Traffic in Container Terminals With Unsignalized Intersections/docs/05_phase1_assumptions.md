# Phase 1 reconstruction decisions

These values are explicit reconstruction defaults, not facts reported by the paper. Every value remains configurable and must be written into future run metadata. Sensitivity analysis begins only after the deterministic Python and one-intersection gates pass.

| ID | Decision | Rationale and validation trigger |
|---|---|---|
| D-01 | VTR cycle length `T = 30 s` | The paper publishes this value only in Example 1. Retain it as the paper-method reconstruction baseline and sweep it after the first end-to-end run. |
| D-02 | HDV extension increment `tau_bar = 1 s` | One simulation step gives deterministic observation boundaries. Sweep it with `T` during calibration. |
| D-03 | Duration resolution `1 s` with minimum-constrained stable largest-remainder allocation | Quantized durations preserve the integer step budget, every positive phase receives at least one step, equal remainders follow input order, and allocation fails when fewer steps than positive phases are available. Floating-second sums are compared within numerical tolerance. |
| D-04 | No HDV extension cap in the paper-method fidelity profile | Algorithm 1 extends until a CAV leads or the queue empties. A `30 s` telemetry-failure cap is allowed only in a separately labeled safety variant, and hitting it must be traced. |
| D-05 | Queue and downstream capacity use vehicle-equivalent slots | `q_ij` counts queued vehicles; `z_jk` counts available downstream vehicle slots. This keeps equations (1)-(3) dimensionally compatible. |
| D-06 | A vehicle is queued at speed `<= 0.1 m/s` | This threshold will be compared with SUMO halting-number behavior during integration. |
| D-07 | HDV-priority stations remain clockwise-stable; other positive-weight stations use descending weight and clockwise ties | This is the narrowest deterministic reading of the prose around Algorithm 2. |
| D-08 | Empty candidate roads use free-flow time `edge_length / 14 m/s` | Equation (8) has an undefined maximum over an empty set. Implemented in the pure routing layer; SUMO sensitivity remains pending. |
| D-09 | Equation (8) uses a `0.1 m/s` speed floor for both the CAV and observed road vehicles | This avoids division by zero. Implemented in the pure routing layer; SUMO sensitivity remains pending. |
| D-10 | Routing ties use stable edge ID order within declared pressure tolerance | The paper does not publish a route tie rule. Implemented independently of candidate input order. |
| D-11 | Phase-transition clearance is `0 s` in the paper-method fidelity profile | The paper requires one active phase and token station in equations (6)-(7) and does not publish an all-red clearance. A `1 s` all-red interval is allowed only as a separately labeled safety variant and is not consumed by Algorithm 2 duration allocation. |
| D-12 | Algorithm 1 uses the queue leader observed after the matching simulation step | The enforcement adapter must apply the current phase, advance SUMO, read the post-step leader, and then evaluate the duration boundary. |
| D-13 | Every zero-duration station is omitted and never becomes a token holder; an all-zero cycle retains the previous holder | Algorithm 2 can list an HDV-priority station whose equation (5) time is zero, but the paper does not define whether this instantaneous handoff changes the next-cycle anchor. This reconstruction recognizes only positive-duration holders. |
| D-14 | `g_c(k)` is completed distance to the current intersection plus candidate-edge length | This implements equation (12) without counting an internal edge twice. The simulation adapter must supply the completed-distance value. |
| D-15 | The Euclidean heuristic ends at the trip's exact configured arrival position | The smoke adapter derives this coordinate from the destination edge's `arrivalPos="max"` endpoint and checks the heuristic against reachable-route distance. The same check remains required for the reconstructed paper network. All routing coordinates use meters. |
| D-16 | Eta starts at `500 m`, decreases by equation (17), and resets only for a new trip | The pure decision is immutable. The smoke TraCI adapter commits the returned eta once after a route mutation succeeds and is verified, not during retries. |
| D-17 | Vehicle-position bounds and route-cost comparisons use separate `1e-9 m` absolute tolerances; all comparisons use `1e-12` relative tolerance; pressure ties use `1e-12 m/s` absolute tolerance | Separating the two distance tolerances prevents a future TraCI observation allowance from weakening equations (15) and (17). These unpublished numerical rules keep eligibility and tie behavior deterministic. |
| D-18 | A defensive precheck reconstructs `R_ij` from candidates marked legal and destination-reachable before Algorithm 3 | This precheck is not an extra step in equations (8)-(17). The smoke topology adapter supplies direct, non-internal, SUMO-reachable outgoing edges and verifies the accepted full route; the general paper-network adapter must preserve the same contract. |
| D-19 | The paper-prose baseline maps equation (8)'s distance term to literal remaining distance; an upstream-lane-position alternative is mandatory sensitivity work | The prose calls the term remaining travel distance, while the formula's physical structure can support the opposite coordinate convention. The baseline adapter will map literal remaining distance as `edge_length - lanePosition`; numerical fidelity cannot be claimed until both interpretations are tested. |
| D-20 | The reconstruction environment uses Windows AMD64, CPython 3.13.13, uv 0.11.16, setuptools 84.0.0, and all SUMO packages at 1.27.1 | The paper does not publish software versions. All components use exact project-local pins, and the verifier rejects mismatched imports, binaries, platforms, or `SUMO_HOME`. Software-version sensitivity remains separate from policy calibration. |
| D-21 | The adapter smoke uses seed `42`, cycle length `10 s`, `1 s` steps and HDV increments, a `180 s` hard cap, CAV maximum speed `10 m/s`, and one `7.5 m` vehicle-equivalent capacity slot | These values make a small deterministic contract test. They are not paper calibration values and must not replace `paper_baseline.toml`. |
| D-22 | The smoke route decision occurs on `cav_src` before `route_split`; completed distance is the full `cav_src` length at that decision node | TraCI requires the current edge to lead the replacement route. Using the node-bound completed length avoids treating a mid-edge observation time as Algorithm 3 path history. |
| D-23 | The paper-grid fixture uses nodes `j_<row>_<column>` at `x = [0,300,600,900,1200] m` and `y = [600,400,200,0] m` | Fig. 6 does not publish coordinates. This deterministic geometry gives 300 m horizontal and 200 m vertical source roads, both within the reported 45-300 m interval, but it does not reproduce the unpublished road-length distribution. |
| D-24 | All vertical links are bidirectional; top and bottom horizontal rows are bidirectional; both middle rows are eastbound | This is the smallest direction assignment matching Fig. 6 arrows and the reported 54 directed roads: `30 + 16 + 8`. Direction and geometry sensitivity remain future calibration work. |
| D-25 | `j_0_1` and `j_0_3` are gate portals on existing boundary nodes, with no extra gate roads | Exact gate connectors are unpublished. Treating gates as metadata preserves the reported 20-intersection/54-road count. Future demand code owns HDV gate-to-internal and internal-to-gate OD construction. |
| D-26 | Every topology-legal non-U-turn movement is generated; one virtual phase contains one incoming approach's movements; phase order is clockwise `N,E,S,W` | Turn permissions and link mappings are unpublished. This mapping guarantees cross-approach mutual exclusion while using SUMO traffic-light logic only as a TraCI actuator for the paper's unsignalized VTR control. |
| D-27 | Paper-grid source roads use `14 m/s` | The paper reports the CAV maximum speed but not a road-by-road speed table. Matching that published vehicle maximum keeps the topology fixture simple; later vehicle and road-speed calibration must remain explicit. |
| D-28 | Generated static virtual phases use a `3600 s` bootstrap duration and self-referential `next` index | This is only a SUMO actuator placeholder, not the VTR cycle or service time. The self-loop prevents automatic phase rotation before TraCI control; its SUMO load warning is expected. The future full-network adapter must override phase state and duration from BP/VTR decisions. |
| D-29 | Every reconstructed paper-grid road has one lane | The paper says most roads are single-lane but does not publish a lane-count table. Applying the predominant pattern uniformly is a reconstruction assumption and requires sensitivity work if multi-lane evidence appears. |
| D-30 | Baseline demand uses a `7200 s` departure horizon and seed `1` | The horizon is inferred from figure axes, while the seed is unpublished. Both are recorded in generated metadata; later stochastic experiments require multiple declared seeds. A full runner must drain beyond this horizon under a separate declared timeout. |
| D-31 | Each aggregate rate is divided into 24 `300 s` bins using cumulative-floor quotas and evenly spaced midpoint departures | This gives exact departure-horizon totals without boundary bursts. For the `2000 vehicles/h` baseline, `[166,167,167]` repeats eight times. The authors' exact progressive-loading sequence remains unavailable. |
| D-32 | CAVs use distinct ordered pairs of strict-internal edges; HDVs use four balanced gate/direction categories over `6` gate-outgoing, `6` gate-incoming, and `42` strict-internal edges | A strict-internal edge has two non-gate endpoints. Reachable OD pairs are sampled uniformly with the configured seed; category counts differ by at most one. Shortest paths use the full grid. Since gate portals add no connector edge, passing a gate-labeled junction does not exit; only an HDV OD endpoint counts as gate use. Metadata gate counts are OD quotas, not observed portal flow. |
| D-33 | The global HDV quota is exact; HDV maximum-speed types `9`, `10`, `11`, and `12 m/s` are globally balanced; CAV maximum speed is `14 m/s` | Exact quotas prevent random penetration drift. Zero speed deviation makes the committed baseline deterministic. The paper does not publish the assignment sampler. |
| D-34 | Every generated vehicle begins on the shortest-distance route returned by pinned `sumolib 1.27.1`, with no internal SUMO edges | Initial routing establishes valid connected trips before IR-BP or HDV runtime decisions. Reproducibility relies on pinned tools, hashed network inputs, and byte-identical rebuild checks; no unpublished equal-distance tie rule is claimed. |
| D-35 | The published HDV `20%` alternative-road probability is runtime-only and is not encoded as a static alternative route | The paper describes a choice at each intersection. The future TraCI runner must implement and trace it; this static-demand milestone validates only initial routes. Unpublished dynamics remain SUMO defaults. |

## Pure algorithm scope boundary

The control slice implements equations (1)-(7), Algorithms 1-2, paper-fidelity cycle execution, and an optional safety-clearance path. The routing slice implements the declared baseline interpretation of equations (8)-(17) and Algorithm 3 over immutable candidates. The one-intersection smoke adapter covers live topology discovery, SUMO route mutation, virtual phase enforcement, destination-arrival handling, and fixture-level heuristic validation. Deterministic builders now cover the declared 20-intersection/54-road topology and seeded static baseline demand. Fidelity and safety-variant results must never be combined. Equation (8) sensitivity, runtime HDV alternatives, the general multi-intersection runner, observed metrics, and numerical calibration remain pending.
